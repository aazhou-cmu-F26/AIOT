1. The project, and where it started

The Statement of Work frames three stages that share one target, one information boundary, one environment and one oracle: Stage 1 a human-led traditional baseline; Stage 2 human-guided AI assistance; Stage 3 a reduced agent. The research question asks how the levels differ in validated success, false candidates, reproducibility, human intervention, cost and failure modes — and the SOW is explicit that findings count only when they pass a shared oracle, and that the goal is to rediscover and validate known bugs, not to find zero-days.

Stage 2 narrows that to a concrete question: given a known, publicly disclosed CVE in a real C library, can current models localise it — and how much does that depend on what the model is shown and how it is asked?

Crucially, Stage 2 did not begin as one experiment. It began as three, built independently:

  • libcoap (contributor "Chen") — conditions labelled C0 / C1 / C2, source supplied as "pack" files.
  • libmodbus (this author) — a "source-review / fuzzing" split, driven through a logging harness.
  • mongoose (a third contributor) — a "traditional / AI-assisted" split, run through a coding assistant whose model was never recorded.

They shared a topic and nothing else: different condition names, different logging shapes, a different (or missing) model identity, different source revisions, and three different ad-hoc scorers. They were not comparable. The entire point of the work this report describes was to make them comparable — to align three fragmented studies onto one methodology so the targets could actually be contrasted.

2. The alignment standard (how consistency was enforced)

A methodology contract replaced the three ad-hoc designs with one. Consistency is enforced by files and tests, not by good intentions:

  1. One condition vocabulary for all targets (table below) — each run belongs to exactly one.
  2. One record schema and one verdict store (verdicts.csv): every run logs its model, prompt, pinned commit, what was disclosed and withheld, cost, repeats and failure mode.
  3. One SHA-pinned source tree per target (vendor/MANIFEST.txt + a per-target target.yaml), with a test proving each condition loads the pinned, vulnerable revision.
  4. One information boundary: de-hinted prompt templates shared across targets, with a test that fails if a non-hinted prompt names the CVE, CWE, fix, mechanism or target function.
  5. One scoring method: blind human-style adjudication against a written per-CVE rubric, stored as data with a rationale — never keyword matching; input-drafting scored only by a runtime oracle.
  6. One statistics convention: per-run units, any-of-3, Wilson 95% intervals, no pooling of non-comparable cells.

3. Two experimental passes

Pass 1 — the initial sweep. The three studies were run out to 11 models × the condition ladder × 3 targets: 279 candidate records, $17.48 of API spend, scored by an automated keyword matcher that called 102 of 277 responses "correct". This produced a headline — a "C1 agentic paradox" (more tools and context made models worse) and "libmodbus is hard (19%)".

The audit. A structured review found the headline unsupported, because the three studies' inconsistencies had leaked into the results:

  • Wrong revision. libmodbus's agentic runs were served v3.1.10, where the bug is already fixed — it literally wasn't present.
  • Leaked answers. Every triage/crash prompt stated the flaw mechanism; mongoose's agentic file-tree named the vulnerable function; libcoap's prompt steered models at proxy code.
  • A broken scorer. Accuracy came from substring matching over converter-written text, so a refusal and several wrong hypotheses counted as "correct"; "19%" also pooled 56 records from a different CVE and counted per-candidate, not per-run.
  • No statistics, no contamination check. single samples, no confidence intervals, and no test of whether a 2022 CVE was simply memorised.

Pass 2 — the aligned correction. Infrastructure was rebuilt to the contract (concrete schema, fixed agentic harness, de-hinted shared templates, pinned trees, a raw-only converter, a Wilson scorer, leak/harness/revision tests). The non-detecting data was quarantined with a written reason. A fresh 234-run sweep ($5.91) was run on the corrected setup; both the old transcripts and the new runs were re-scored by blind rubric into one verdicts.csv; runnable oracles and three tool baselines were added. The rest of this report is the result.

4. Results

4.1 What the first pass claimed vs what the data shows

The "19%" for libmodbus C0 was a scoring artifact — the same answers re-scored are ~69%. The "100%" and "89%" crash-given numbers were overstated by local models being graded as fully correct. And mongoose's agentic "83%" collapses to 30% once the file-tree annotation that named skip_chunk is removed — the hint, not the model, was doing the work.

4.3 The contamination control — the result that reframes the rest

libmodbus's numbers are a memorisation-inflated upper bound. The clean evidence of genuine capability comes from libcoap and mongoose, whose CVEs post-date every model's training cutoff. Several models also hallucinated plausible CVE ids — a caution against trusting recalled identifiers at all.

4.4 The "agentic paradox", dissected

The first pass's central claim — that tools and context made models worse — does not survive the aligned redo. Three mundane causes explain it: a file-tree annotation (removing it drops mongoose C1 from ~83% to 30%); genuine difficulty of un-annotated search (libcoap C1 is 8% — only one model navigated the 96-file tree to the bug); and content moderation (many agentic runs returned 0 bytes, now recorded as filtered and excluded, not counted as failures). A related effect: for libcoap, handing the model the excerpt (triage, 67%) beats hiding the bug in a 4-file set (one-shot, 0%). The bug is easy to explain and hard to find. One model re-found a genuine, separate proxy use-after-free along the way — recorded as a real non-target finding, not a miss.

4.5 Handing over the bug is not enough (input-drafting, oracle-scored)

In input-drafting the vulnerability is given and the model only has to produce a trigger frame. Scored by replaying each frame through a live AddressSanitizer server, only 2 of 12 libmodbus frames actually fired the bug (confirmed at modbus.c:980). The rest failed instructively: one model refused on moderation ("a ready-to-send exploit for industrial software"), and the 7B local models produced malformed Modbus framing. Capability here is gated by safety behaviour and protocol precision as much as by understanding.

4.6 Tool baselines — the real yardstick

cppcheck flags exactly the one classic-pattern bug — libmodbus's duplicated condition — and misses both semantic bugs; note that the one it catches is also the contaminated one. In fuzzing, AI-drafted seeds reach the crash ~6× faster than naive seeds (median 38 vs 226 iterations). This reverses the first pass's single-trial claim that AI seeds "found nothing"; the honest caveat is that the AI corpus contained two confirmed triggers, so a seed near the crash needs little mutation.

5. Integrity — mistakes caught in the corrected pass itself

A clean-experiment claim is only credible if it reports its own errors. The corrected pass made three, each caught by a sanity check rather than assumed away: a resume-dedup bug that wasted ~$4.28 on redundant runs (caught when "runs completed" exceeded the matrix); a de-hinted crash-given prompt that shipped no source (caught when models refused to localise without code); and a wrong server config in input-drafting (caught when a hand-built trigger fired but the model frames didn't). None changed a conclusion — but each would have quietly biased a result if unquestioned, which is the exact failure mode this work exists to avoid.

6. Budget

Pass 1 cost $17.48 against an SOW ceiling of "about $5, under $10" — ~28% of it on runs that could not detect the bug (wrong CVE / fixed revision). The corrected pass added $5.91 of useful spend (plus ~$4.28 lost to the dedup bug, logged). Future spend was gated on explicit approval.

7. Limitations

  • Single-rater verdicts. No human second pass; inter-rater agreement unmeasured (a blinded packet set is staged).
  • Model-mix confound. crash-given / C0 / triage ran on cheap+local models only, so those are not comparable to the frontier-inclusive agentic rows.
  • Small n. cells are 9–13 runs; CIs are wide.
  • Oracle coverage. only libmodbus input-drafting has a runnable oracle so far.
  • No completed human baseline. the compliant kit exists but has not been run; contamination means any "time-to-find" metric would be carryover-biased anyway.
  • Contamination is self-reported by the models in the recall probe.

8. Conclusions

With contamination controlled and the answer kept out of the prompt, current models localise a memory-safety bug reliably when handed the right excerpt or an ASan report (triage/crash ≈ 50–67% on the post-cutoff targets), but agentic needle-in-a-haystack discovery is hard (8% on libcoap) and turning a known bug into a working trigger is harder still (2/12). A free linter already catches the one classic-pattern bug — which is also the one the models had memorised.

The defensible claim is not "AI finds vulnerabilities," but: AI meaningfully assists a human who has already narrowed the search — as a triage reader and a fuzzing-seed generator — on exactly the semantic bugs that cheap tools miss, with reliability still bounded by safety refusals, context limits, and how much the task points the way.

And methodologically: the value of this exercise was the alignment — three incomparable case studies pulled onto one pinned, de-hinted, blind-scored, oracle-backed standard, so that for the first time the three targets can be read side by side and the headline claims can be checked rather than believed.
